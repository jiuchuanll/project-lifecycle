# Closure and Retention

Use this reference after delivery verification to record the durable outcome, assess exact Feedback coverage, hand off a bounded knowledge candidate, select retention, and clean runtime state. Route definitions remain owned by [Intake routing](intake-routing.md).

## Closure Gate

Require an owner outcome, verification result, acceptance decision where needed, residual risks, exact Feedback coverage, blocking-obligation disposition, conflict disposition, and knowledge-handoff result. A partial outcome must say which criteria and coverage remain open. Cancellation or withdrawal preserves why work stopped without claiming acceptance.

## Knowledge Handoff

Produce one schema-valid Knowledge Diff candidate from accepted delivery evidence, or an explicit no-change result. Bind it to the starting and target baselines, stable domain/fact ownership, exact evidence references, and operation semantics. Do not copy PRD prose, source bodies, chat logs, or hidden reasoning.

The candidate is not current truth. Only `maintain-project-knowledge` may validate conflicts, obtain the required semantic approval, and apply accepted knowledge writeback.

## Retention

Keep active material while delivery or a bounded repair remains open. At closure, retain a compact summary containing identity, outcome, acceptance, evidence, coverage, residual risk, and knowledge-handoff reference. Move detailed delivery evidence to archive only when policy requires retention; superseded or redundant intermediate artifacts leave default retrieval.

Archive lookup later is receipt-gated by the knowledge Skill. Do not keep large bodies in active indexes merely because they existed during delivery.

## Runtime Cleanup

The Context Receipt is task runtime state, not a committed product asset. Delete it only after the durable closure outcome, verification, conflict disposition, and Knowledge Diff or no-change result are recorded. Remove only the exact PRD receipt and its empty runtime directory; never delete a sibling PRD, worktree, durable delivery file, backup, or unresolved cleanup evidence.

If exact cleanup cannot be verified, preserve a bounded cleanup-pending signal for retry rather than claiming completion.
