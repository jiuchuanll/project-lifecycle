# ZCode installation

Candidate version: `0.7.0`. Evidence status: `NOT_TESTED` until the native matrix is complete. Retained `0.1.0` traces are historical evidence, not validation of this candidate. The discovery mechanics below were verified by static inspection of the installed ZCode desktop host and are not native run evidence.

ZCode ships no standalone plugin CLI. Marketplaces are added in the client under Settings → Plugin Management → Discover with the `+` button, which accepts `https://github.com/jiuchuanll/project-lifecycle`, another Git URL, or a local directory. The host locates the marketplace manifest at `.claude-plugin/marketplace.json` (a root `marketplace.json` is the fallback) and each plugin manifest at `.zcode-plugin/plugin.json` first, so the repository root is directly addable as a marketplace. A directory source is copied into the plugin cache as is, so add a clean release snapshot instead of a development tree.

Install the `project-lifecycle` card from that marketplace. ZCode materializes the plugin under `~/.zcode/cli/plugins/cache/<marketplace>/project-lifecycle/<version>/`, records the install in its plugin registries, and enables the id `<name>@<marketplace>` under `plugins.enabledPlugins` in `~/.zcode/cli/config.json`. That marketplace copy, cache, registry, and enable map are the only supported install state; writing them by hand is migration rather than installation, and a partial hand copy loads nothing.

Reload ZCode and open a new session (Skills resolve at session start), verify `maintain-project-knowledge` and `run-prd-lifecycle` are discoverable, and run `<plugin-root>/bin/project-lifecycle version` (fallback `node <plugin-root>/dist/project-lifecycle.mjs version`), expecting `{"ok":true,"value":{"version":"0.7.0"},"errors":[]}`. Uninstall from the plugin detail view and reload to remove before retesting a clean state. Record the ZCode version, marketplace identifier, manifest path, and redacted diagnostic; do not fall back to a copied Claude Skill tree.
